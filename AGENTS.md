# Правила проекта

## Тултипы мультиблоков IMPACT

- В одном тултипе вызывать `addMachineType()` ровно один раз. В этом вызове
  допускается перечислять несколько типов машин. Повторные вызовы запрещены.
- Порядок обычного тултипа: необязательная короткая вводная информация, затем
  тип машины, затем остальные сведения. Описание параллелей размещать после типа
  машины; перед типом машины оно не допускается.
- Общий текст о параллелях добавлять через `ImpactMultiblockTooltipBuilder.addParallelInfo()`.
  Использовать локализацию и оформление базового `MultiblockTooltipBuilder` GregTech.
  Если у машины другая схема параллелей, описывать её фактическое поведение
  вместо стандартного текста; не подставлять базовые 1–256 вопреки коду машины.
- Стандартное описание канала автоматической установки люков добавлять через
  `ImpactMultiblockTooltipBuilder.addHatchChannelInfo()`.
  Вызывать его после описания голограммы, в разделе каналов. Порядок вызовов
  в коде должен соответствовать порядку разделов. Сохранять одну непрерывную
  цепочку `return new ... .toolTipFinisher();`; IMPACT-билдер должен поддерживать
  вызовы хелперов на своих местах без промежуточных переменных и разрыва цепочки.
- При создании и переработке тултипов не добавлять инструкции о переключении карты
  рецептов отвёрткой и настройке разделения входов. Эти настройки доступны в GUI;
  отдельные пояснения в тултипе не нужны.
- Эти правила не являются поручением массово менять существующие тултипы.

## Единые названия специальных люков и шин

При создании и переработке тултипов использовать названия из таблицы во всех
разделах, включая легенду голограммы и описания каналов. Количество, уровень,
ёмкость, допустимое место и назначение указывать отдельно от базового названия.
Названия относятся к реальным блокам IMPACT, сверенным с `Basic_Register` и
конструкторами блоков; не заменять их произвольными синонимами.

| English | Русский |
| --- | --- |
| Parallel Receiver | Параллельный приёмник |
| Parallel Transmitter | Параллельный передатчик |
| Communication Receiver | Коммуникационный приёмник |
| Communication Transmitter | Коммуникационный передатчик |
| Parallel Computer Rack | Стойка параллельного компьютера |
| Miner Drill Hatch | Буровой люк |
| Miner Enrichment Unit | Блок обогащения |
| Nuclear Rod Hatch | Люк ядерных стержней |
| Tank Input and Output Hatch | Люк ввода и вывода бака |
| Cargo Aerostat Hatch | Грузовой люк аэростата |
| Matrix Particles Chamber | Камера матричных частиц |
| ME Connector | ME-коннектор |
| Primitive Input Bus | Примитивная входная шина |
| Primitive Output Bus | Примитивная выходная шина |
| Primitive Output Hatch | Примитивный выходной люк |
| Pump Output Hatch | Выходной люк помпы |
| Steam Input Hatch | Паровой входной люк |
| Steam Output Hatch | Паровой выходной люк |
| Non-serviceable Maintenance Hatch | Необслуживаемый люк обслуживания |
| Debug Parallel Receiver | Отладочный параллельный приёмник |

- Не использовать `Parallel Hatch`, `Parallel Input Hatch`, «параллельный порт»
  и другие замены для `Parallel Receiver` / «Параллельный приёмник».
- Не сокращать коммуникационные приёмник и передатчик до безымянного
  `Receiver` / `Transmitter`; не смешивать их с параллельными.
- `GTMTE_OreHatch` — `Miner Drill Hatch`, а не `Ore Output Hatch`.
- Лазерные люки не упоминать отдельно в описаниях мультиблоков: это улучшенные
  варианты обычных энергетических люков. Входные варианты обозначать как
  `Energy Hatch` / «Люк энергии», выходные — как `Dynamo Hatch` / «Динамо-люк».
  Их количество учитывать в общем лимите соответствующих энергетических люков.
- Для стандартных люков и шин GregTech сохранять стандартные названия.
  Не добавлять `Fluid` / «жидкостный» к `Input Hatch` и `Output Hatch`.
- Отладочный приёмник упоминать только там, где описание относится к самому
  отладочному блоку; не добавлять его в требования обычных мультиблоков.
